# Безпека

Цей документ описує властивості, які можна встановити з поточного коду. Він не є аудитом backend-бінарника чи постачальника OpenCode.

## Наявні запобіжники

- Маніфест запитує лише `android.permission.INTERNET` серед дозволів; `allowBackup` вимкнено.
- Завантаження виконується через HTTPS URL, із connect timeout 15 секунд і read timeout 60 секунд; результат спершу пишеться у тимчасовий файл і перейменовується.
- CI має мінімальний `contents: read` для репозиторію. PR workflow не має права змінювати вміст репозиторію чи створювати реліз.
- Workflow будує лише debug APK і завантажує його як артефакт дії.

Ці властивості не замінюють перевірку джерела/підпису файлів, захисту залежностей або тестування на пристрої.

## Відомі ризики та обмеження

- URL OpenCode містить `latest`, а код не перевіряє хеш чи підпис архіву/бінарника. Вміст може змінитися між збірками/запусками; зафіксувати версію та перевіряти криптографічний хеш необхідно до продуктивного використання.
- `fake-chroot-ng` має надаватися окремо як виконуваний arm64-бінарник. Репозиторій не містить його вихідного коду чи перевірки походження/хешу. Його можливості й гарантії ізоляції тут не аудовані; назва rootfs-контексту не є доказом безпеки ізоляції.
- Перевірка відповіді HTTP відбувається після копіювання потоку, а завантаження/розпакування не має явного ліміту розміру. Код tar-розпакування шукає запис з назвою `opencode`; перевірка підпису, контроль походження та захист від зловмисного архіву не заявлені.
- Завантажений файл виконується як окремий процес у контексті застосунку. Код успадковує оточення процесу та не задає явний мінімальний PATH/CA-набір. Не запускайте неперевірені модифікації застосунку або backend.
- Існує лише порожній каталог `files/env/rootfs`; немає реалізованого механізму встановлення rootfs, інтерактивного PTY чи перевірки очікуваної ізоляції. Фактичну поведінку треба валідувати на цільових пристроях.
- CI використовує версійні теги GitHub Actions (`@v4`, `@v3`), а не зафіксовані commit SHA. Це зручність, але не гарантія незмінності залежностей workflow.

## Практичні рекомендації перед релізом

Зафіксувати версію CLI та backend, отримувати їх з контрольованих джерел і перевіряти опубліковані хеші/підписи до запуску; обмежити розмір завантаження та обробляти невдалі HTTP-відповіді до запису; визначити й протестувати модель ізоляції та складання rootfs; перевірити SELinux/W^X і процесні дозволи на реальних пристроях. Ці пункти є рекомендаціями, а не вже реалізованими гарантіями.
